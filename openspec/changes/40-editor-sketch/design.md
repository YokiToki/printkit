# Design

## Context

`39` gives a scene of objects (imported meshes and primitives), selection, transforms, history, and a viewport with a scene API. `40` adds the CAD loop: sketch → constraints → feature. Rule 2a of `openspec/EDITOR.md` applies: the sketch and feature parameters are the source of truth, the mesh is derived and can be rebuilt (also at a higher resolution for export). Geometry stays React-free and free of three.js; the worker builds meshes with `manifold-3d`.

## Goals / Non-Goals

**Goals**: a sketcher that is pleasant for the common cases (brackets, plates with holes and slots, rounded rectangles, revolved knobs), predictable constraints, exact profiles, parametric recompute.

**Non-Goals**: everything listed as out of scope in the proposal; matching Fusion's UI; a general-purpose CAD constraint solver.

## Decisions

1. **Data model.** `Sketch = {id, name, plane, visible, points: Record<id, {x, y, fixed?}>, curves: Record<id, Curve>, constraints: Constraint[]}` in sketch millimetres, X right and Y up in the plane. `Curve` is `line {a, b}` | `circle {c, r}` | `arc {c, a, b}` (counter-clockwise from `a` to `b`; the radius is the distance to `a`, an internal "equal radius" constraint keeps `|cb| = |ca|`); every curve has `construction: boolean`. Points are shared by id, so "coincident" of endpoints is structural (merging) and the constraint kind remains for point-on-point cases made by hand. `Plane = {origin, normal, xDir}` derived from `{base: 'XY'|'XZ'|'YZ', offset}` (a face reference is `44`). Stored positions are the solved ones.
2. **Constraints** are plain data `{id, kind, refs, value?}`: `coincident`, `pointOnLine`, `pointOnCircle` (circle or arc), `horizontal`, `vertical` (line or two points), `parallel`, `perpendicular`, `tangent` (line–circle/arc, circle–circle/arc), `equal` (lengths or radii), `symmetric` (two points about a line), `midpoint`, `fixed`; dimensions `distance` (point–point, point–line, plus `dx` / `dy` variants), `radius`, `diameter` (the same constraint, a display flag), `angle` (two lines). Each kind is one residual function with an analytic Jacobian row. Dimensions are driving; reference (measured) dimensions are out of scope.
3. **Solver: own Levenberg–Marquardt, zero dependencies** (decision to be confirmed by the spike in task 1.1). The variables are the free point coordinates and circle radii; residuals are the constraints; a Jacobian is assembled sparsely; the damped normal equations are solved with Cholesky/LDLᵀ for ≤ 400 variables (a sketch is small). Dragging adds a weak "stay close to the mouse" residual and a stronger "stay close to the previous positions" one so the solution is the nearest one and does not jump to the mirrored solution. Degrees of freedom = variables − rank(J), rank from a QR with column pivoting; an entity is *fully defined* when its variables have no component in the null space; conflicts/redundancy come from the rank of J restricted to constraint rows (a minimal conflicting set by removing constraints one by one until the rank grows). Convergence tolerance 1e-9 mm, max 50 iterations; a non-converging solve leaves positions unchanged and reports `sketch.error.noSolution` with the last residuals. Candidates if the spike favours it: `planegcs` (FreeCAD, WASM) — only if its licence is compatible with a GitHub Pages static site and the size is below 300 KB; otherwise the own solver stays.
4. **Macros, not new entity types.** Rectangle = 4 lines + 4 shared points + 2 horizontal + 2 vertical (+ width/height dimensions when typed); with a corner radius it is followed by four `Fillet` operations with an `equal` radius constraint and one radius dimension, so changing the radius changes all four. Slot = 2 lines + 2 arcs + tangents + equal. Regular polygon = n lines + `equal` + points on a construction circle. Fillet(corner) = trim the two lines at the tangent points, add an arc, add `tangent` constraints and a `radius`; Chamfer = trim and a line with a distance dimension. The macros are pure functions `(sketch, args) → patch` and are individually tested.
5. **Inference while drawing.** Cursor snaps (priority order): existing point (coincident), curve end tangent direction, midpoint, point on curve, horizontal/vertical alignment with the previous point (within 3° or 6 px), grid. The matched rule is shown as a glyph next to the cursor and becomes a constraint on click. `Ctrl` disables inference, `Shift` locks the axis.
6. **Profile extraction** (`geometry/features/profile.ts`, pure): take non-construction curves, build a graph on shared points (points closer than 1e-5 mm are merged), find simple cycles, report dangling ends (`sketch.error.openProfile` with the point) and crossings (`sketch.error.selfIntersect` with the position), orient (outer counter-clockwise, holes clockwise), build nesting by point-in-polygon tests of one vertex, and discretise to polygons with an adaptive chord tolerance (default 0.01 mm, at least 16 segments per circle, 96 for the full circle at default quality; the quality is a parameter of the build, not stored in the sketch). Overlapping loops that are not nested are an error in v1 (a planar-arrangement regions step is future work); this keeps the region list simple: one region per outer loop with its holes.
7. **Features** (`geometry/features/*`): `Extrude {sketch, regions: 'all'|id[], side: 'one'|'symmetric'|'two', d1, d2?, op: 'new'|'join'|'cut'|'intersect', top?: EdgeBreak, bottom?: EdgeBreak}` and `Revolve {sketch, regions, axis: {kind:'line', curve} | {kind:'planeAxis', axis:'x'|'y'}, angle, op}`. Extrude = `CrossSection.ofPolygons(..., EvenOdd)` → `Manifold.extrude`; Revolve = profile moved to the axis frame → `Manifold.revolve(cs, segments, angle)`; a profile that crosses the axis is `sketch.error.revolveCrossesAxis`. A body is `source: {kind:'feature', features: Feature[]}`; `evaluateFeatures(features, sketches, quality)` applies them in order; the first feature must be `new`, later ones act on the body so far (`join` unions, `cut` subtracts, `intersect` intersects); a failed feature stops the evaluation, returns the previous solid and reports which feature failed (the UI marks it). A feature whose sketch is missing or empty is a failure, not a crash.
8. **Edge chamfer/fillet of the extrusion caps (`EdgeBreak {kind:'chamfer'|'fillet', size}`).** Built without B-rep edges: the cap is lofted from the profile to its mitre-offset (vertex-to-vertex correspondence, so the topology is the same), one sloped band for a chamfer and N bands following a quarter circle for a fillet (N from the 0.02 mm sagitta, 4–16), as a triangle mesh handed to Manifold. Allowed only while the offset does not collapse any vertex or edge (size < half of the smallest feature length / sharpest-corner limit); otherwise `sketch.warning.edgeBreakTooLarge` and the break is skipped. Concave corners use the mitre as well. The spike (1.2) builds this on a rounded rectangle with a hole and a slot and records the limits; if it is not robust enough, the field stays in the model but the UI offers only chamfer for convex-only profiles.
9. **Viewport.** `Viewport` gets an optional `sketch` prop `{plane, sketch, selection, preview, tool, grid}` and callbacks `onSketchPointer(kind, x, y, mods)`. The layer draws curves (line segments with a screen-constant width, arcs as polylines), points, constraint glyphs (sprites at curve midpoints), dimension labels (CSS2D-style DOM labels positioned from plane coordinates, editable on click) and the plane grid. In sketch mode the camera is orthographic looking along the plane normal; wheel and middle-drag pan/zoom; rotation is locked until the sketch is finished (the ViewCube is disabled but "Look at plane" resets the view). Picking in the sketch layer uses screen-space distances to curves and points (6 px), independent of the scene raycaster.
10. **History and persistence.** Sketch commands (`addCurve`, `moveFromDrag`, `addConstraint`, `setDimension`, macros, `deleteSelection`) go through the editor's `dispatch(label, patch, mergeKey)` with merging for drags and dimension typing. A solver run is part of the command: it returns the new positions together with the patch, so undo restores positions without solving. `doc.sketches` is added to `SceneDoc` (optional field, schema stays 1; `migrateScene` normalises every number and drops constraints that refer to missing ids, logging them). Features reference sketches by id; deleting a used sketch asks for confirmation and marks the dependent features as failed.
11. **Recompute.** Changing a dimension → solve (main thread, ≤ 16 ms target for 200 entities) → patch → the worker rebuilds only the bodies that use that sketch (cache key `(feature list, sketch versions, quality)`); the preview while an Extrude dialog is open uses a coarser quality and the same pipeline.
12. **SVG import** (`geometry/svg.ts`, pure, no DOM parser dependency beyond `DOMParser` in the main thread): supported elements `path` (M L H V C S Q T A Z, absolute and relative), `rect` (rx, ry), `circle`, `ellipse`, `line`, `polyline`, `polygon`, `g` transforms (matrix, translate, scale, rotate, skew); `use`, text, images, CSS and clipping are ignored with a notice. Units: user units to mm by a dialog (default 96 dpi, i.e. 0.2646 mm per unit, or "fit width to N mm"); curves (Bézier, ellipse) are flattened to the chord tolerance; arcs and circles stay arcs and circles when the transform is a similarity. Y is flipped (SVG down → sketch up). Limits: 50 000 segments, file ≤ 5 MB, otherwise refused with a message.
13. **UI structure.** Entering sketch mode swaps the tool bar to: Select, Line, Rectangle▾ (2 corner, centre), Circle, Arc▾, Slot, Polygon, Fillet, Chamfer, Trim, Mirror, Construction, Dimension, Constraints▾, Finish. Properties show the selected curve, its constraints and an editable list of dimensions (each a `LengthField`). The status bar shows `Sketch 1 · 3 DoF` / `Fully defined` / `Conflict`. Feature creation is in the Add menu of the scene mode (Extrude, Revolve) and opens a side dialog (not a modal) with live preview; the body's features are listed in the outliner under the body and in its properties, each editable, deletable (with re-evaluation) and marked when failed. No artboard exists; screens are built from `ui/` components and tokens, compared with the wireframes below.
14. **Hotkeys** extend the registry of `39` (active only in sketch mode): `L` line, `R` rectangle, `C` circle, `A` arc, `D` dimension, `X` construction, `T` trim, `F` fillet, `Enter` finish, `Esc` cancels the current tool, then clears selection, `Delete` removes the selection, `H`/`V` add horizontal/vertical to the selected line.

## Risks / Trade-offs

- **Solver quality is the product.** A weak solver (jumping to mirrored solutions, slow drag, vague errors) ruins the sketcher. Mitigations: nearest-solution damping, a regression set of 30 reference sketches (rounded rectangle, slot, gear-like polygon, bracket with holes, tangent chains) with expected DoF, and the spike comparing with `planegcs` before committing to the own solver.
- **Overlapping profiles are rejected.** Fusion users draw overlapping shapes and pick regions. v1 asks for non-overlapping loops (clear error with the crossing point). A planar-arrangement step can be added later via `CrossSection` booleans without changing the stored data.
- **Edge chamfer/fillet via offset loft** is the least certain geometry here (collapse, concave corners, tiny holes). It is isolated (`edgeBreak.ts`), optional in the UI, and the spike decides how much of it ships.
- **No topology naming.** Features reference sketches and sketch curves by stable ids, never mesh faces, so sketch edits cannot break references; face-based sketches (`44`) will add a face reference that must survive edits and are left out here on purpose.
- **Discretisation.** Curves become polygons at build time. Exports at the default quality are visibly smooth (96 segments per circle); the quality setting for export is a later option, the data already allows it.

## Open Questions

- Own solver or `planegcs` (spike 1.1: licence, size, speed on 200 entities, quality of DoF/conflict reporting).
- Whether the Slot and Polygon macros stay in v1 if the schedule is tight (they are independent tasks and can be dropped without changing the model).
- Whether the sketch plane offset needs a plane object of its own now (kept as two numbers on the sketch).
