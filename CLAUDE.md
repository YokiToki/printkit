# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` — Vite dev server
- `npm run build` — `tsc --noEmit` (type check) and then `vite build` into `dist/`
- `npm test` — `vitest run` (all tests)
- Single test: `npx vitest run src/baseplate.test.ts -t "<test name>"`

There is no linter configured.

## Workflow

Work is planned as numbered OpenSpec changes in `openspec/changes/NN-name/` (order and dependencies: `openspec/ROADMAP.md`). Take them strictly in numeric order, one change at a time.

1. **Pick the change.** The lowest-numbered active change (`openspec list`). Every change under its "Depends on" line must already be archived; otherwise stop.
2. **Apply.** `/opsx:apply NN-name`. Read proposal, specs, design and tasks before coding. Do the tasks in order, keep each one minimal and focused, and tick its checkbox (`- [x]`) right after it is truly done, with the behaviour from the spec fully implemented, not partly or deferred. If a task is unclear, needs extra scope or contradicts the design, stop and update the artifacts (`/opsx:update`) instead of guessing.
3. **UI tasks follow the design.** Each cites an artboard in `design/artboards/` (map in `design/README.md`). Build with the `ui/` components and Tailwind tokens from `theme.css`, no ad-hoc colours or sizes. Compare the result with the artboard in the browser, in both en and ru, and at 390 px if the layout changes. If no artboard exists, build from the component library and say so in the task.
4. **Rules for every task.**
   - All UI text goes through i18n: add keys to both `en.json` and `ru.json`.
   - Lengths are stored in mm; use `LengthField` for any length.
   - Geometry stays React-free in `geometry/`; add or update a vitest test with the task (geometry: validity and bounding box; UI: component test).
   - Verify what the task names (browser check, STL bbox/volume), not only that tests pass.
5. **Before closing a task section.** `npm test` and `npm run build` are green; the dev server starts and the console has no errors. Commit after each completed task section with a message that names the change, for example `04-fastener-placement: add FastenerSection`.
6. **Version.** Every change raises the semantic version (`package.json` is the single source, shown on the site as `v<version>`; the footer and the beta notice read it through `APP_VERSION` in `app/site.ts`): minor for a new feature, mode, pattern or option, patch for a fix or rework without a new capability, major for an incompatible change (stored settings that cannot be migrated, removed or moved routes). The target version is stated in the proposal; the bump (`package.json` plus a line in `CHANGELOG.md` naming the change) is the last implementation task, before verification. 1.0.0 is the release of `29-beta-label`; changes before it do not bump.
7. **Finish.** When all tasks are `[x]`, run `/opsx:archive NN-name` (sync specs, then archive) and commit. Archive in numeric order so the main specs stay consistent. Update the Architecture section below if the structure or conventions changed.

Changing the plan itself (new requirement, reorder, split a change) goes through `/opsx:update` or `/opsx:propose`, not by editing code first. Keep `openspec/ROADMAP.md` and the "Depends on" lines in sync when numbers change.

## Architecture

PrintKit is a client-only React 19 + TypeScript app (Tailwind CSS v4, Tabler Icons, react-router hash routes, i18next) with parametric tools for 3D printing: Gridfinity parts, keychains and (planned) rack parts. It previews them in 3D and exports binary STL and 3MF. There is no backend. Planned work lives in `openspec/changes/NN-*` (build order in `openspec/ROADMAP.md`); the visual design is in `design/` (artboard → task map in `design/README.md`).

Layout of `src/`:
- `app/` — entry (`main.tsx`, `App.tsx`), `products.ts` + `modes.tsx` (registry of product sections, all with modes: `gridfinity` box/baseplate/cutout, `keychain` image/shape, `rack` panel + case + shelf; a mode is `{id, path, Icon, labelKey, startKey}`; a new product = one entry + routes), `routes.tsx` (hash router: `/` product chooser `StartPage`, `/gridfinity`, `/keychain` and `/rack` mode chooser `ModeChooser(product)`, `/gridfinity/{box,baseplate,cutout}`, `/keychain/{image,shape}`, `/rack/{panel,case,shelf}`, unknown subpaths go back to the product's chooser; legacy `/box|/baseplate|/cutout` redirect to the new paths, unknown → `/`), `StartLayout` (shared start-page frame, `ChoiceCard`, number hotkeys), `AppShell`, `Header` (product switcher, mode switcher for products that have modes, mm/in, EN/RU; logo text = active product), `StartPage`, `Workspace` (parameter panel + sticky footer + viewport; bottom drawer below 768 px), `usePersistedState`, `lastSession` (`gridfinity.last` stores product and mode as a string; old records without product read as gridfinity, a keychain record without mode leads to the chooser), `theme.css` (Tailwind `@theme` tokens from the design).
- `ui/` — generic controls with no domain knowledge: `Section` (always starts collapsed, no `defaultOpen`; `modified` colours its summary with the `--color-changed` token and adds "(changed)" to the toggle's accessible name; compute it with `isChanged(slice, defaults)` from `ui/isChanged.ts`, using the same slice that the section's Reset writes, in mm so units never matter; sections whose summary is not a setting — file name, cutout list/selection/placement — never pass it), `ConfirmDialog`, `Toggle`, `SegmentedControl`, `NumberField`, `LengthField`, `Banner`, `Button`, and units (`units.ts`, `UnitProvider`).
- `features/{baseplate,box,cutout,viewport}/` — a mode owns its panel, params and persistence key. `ComingSoon` (app/) is the placeholder for modes or products that are not built yet; nothing uses it now.
- `geometry/` — React-free CSG kernel, see "Geometry package" below.
- `i18n/` — `en.json`, `ru.json`, init with language detection.

Geometry package (`src/geometry/`, no React or three.js imports):
- `spec.ts` — Gridfinity constants (pitch 42, layer stacks `SOCKET_LAYERS`/`FOOT_LAYERS`, clearance, radii, fastener sizes). Pitch is a parameter everywhere, never read from a constant inside builders.
- `profiles.ts` — `layeredHull` is the one profile builder (low chamfer / wall / up chamfer); `socketPocket`, `binFoot`, `lipProfile(style)` are data-driven wrappers. Profile slabs overshoot the nominal top by `SLAB_T` (0.001 mm) on purpose, for clean cuts.
- `thickness.ts` — `Thickness` defaults and `validateThickness` (returns i18n keys `thickness.*`, never text). `sizing.ts` — `resolveAxis(size, pitch, align)` → cells, padding, offset, truncated.
- `footprint.ts` — `Footprint` (cells, size, offsets; origin = footprint centre), `footprintFromCells/Size`, `cellCenters`. `fasteners.ts` — `FastenerConfig` (per kind `{mode: none|corner|full|manual, slots: Slot[]}` + sizes/presets/tolerance/`earWall`). Holes only exist at the standard cell-corner positions (13 mm from the cell centre); Manual is a selection of `Slot`s (cell i,j + corner), stored per slot so it survives grid resizing, and switching to Manual always starts empty. `resolvePositions`, `fastenerCuts(w, config, footprint, floor)` (hole cutters + the position list the 2D editor shows), `cellWindows` (per-cell open windows below the pocket minus the ears), `fastenerEar`, `checkFasteners` (warning keys). Fasteners never add a full floor: the baseplate keeps material only in ears (hull of a disc around the hole and the window corner) of height `FLOOR`, so total height is 4.65 + 4 mm. Old stored coordinates snap to slots within 3 mm (`slotsFromPoints`, `features/baseplate/migrate.ts`). Any mode that supports fasteners reuses these and `features/fasteners/FastenerSection`.
- `split.ts` — `SplitSettings` (persisted: bed source/size, margin, auto or manual cuts, connector, exploded view) → `splitGeometry` → `SplitGeometry`; `autoCuts` (fewest parts, cells spread evenly, remainder to the first parts, rim/padding stay in the edge parts), `resolveCuts`, `splitParts` (labels A1, B1…: column letter + row number; each part has its rectangle, so the union of parts is the plate). `connectors.ts` — `ConnectorConfig` (none | holes | dovetail, per-cut overrides), `cutFaces` (faces between parts, with `ribs` = cell boundaries strictly inside the face), `planFace`, `connectorExtras`. Holes (presets: filament 1.75 → Ø1.9, pins 2/3 mm, magnets 3×2 and 2.8×0.75; default filament, depth 6 mm) are drilled **along the rib that meets the cut, into its end face**, in both parts, at the rib ends nearest to the evenly spaced count/inset positions; they are blind (depth = min(configured, part length − 2 mm)), never reach a socket, and a face with no rib end (one cell wide) reports `connector.noRib`. The dovetail lies flat on the bed: the key spans z = 0…`dovetailHeight` (2 mm) on part A, the socket in part B is open at the underside and closed `clearance` above the key, so parts join by lowering one onto the other; its depth is checked against the wall width (`dovetailFits`, ≈ ≤ 1.2 mm). Collisions with fastener holes move/skip connectors and issues come back as `connector.*` keys; stored removed presets (m3, m6x2) load as `custom`.
- `wasm.ts` — `getWasm(wasmUrl?)`, one WASM module per thread; the url is optional so tests run in Node. `model.ts` — `generate(mode, params)` dispatches by mode and returns a `ModelResult` (`parts: PartMesh[]` = label, col, row, oversize, `MeshData`; one part `A1` when there is no split); new modes are added to `ModeParams` there. `buildBaseplate` builds the whole plate (tests, comparisons), `buildBaseplateParts` builds each part directly from its cell range (`buildPlate(w, g, part, extras)`), so all parts share the same height and edge parts keep rim, padding and rounded corners. `worker.ts` + `modelClient.ts` — the worker owns WASM; the client makes the latest request win and drops stale replies. UI side: `app/useModel(mode, params)` (debounce 150 ms, `busy` after 200 ms, `pending` while the mesh is stale, previous mesh kept on error).
- Tests: use `expectValidSolid` from `testing.ts` (status, non-empty, volume > 0, optional bbox). When refactoring geometry, add a volume + bbox regression case first and keep it green.

Conventions:
- **Geometry is built with `manifold-3d` (WASM), not three.js**, and runs in a Web Worker. The rest of the app only sees `ModelResult`/`MeshData` (typed arrays + bbox + volume), never `Manifold` objects. `Viewport` takes a `ModelResult` plus the exploded `gap` (parts are moved in the scene only; geometry stays in assembled coordinates) and `toBinaryStl` takes one `MeshData`. `Viewport.tsx` is imperative: the three.js scene is created once in a mount effect and driven through an `api` ref. Z is up. The camera orbits freely, also below the XY plane (to inspect magnet pockets and ears on the underside): the ground grid and the build plate overlay fade out with `groundOpacity(cameraZ, distance)` (`features/viewport/ground.ts`) and a second light from below keeps down-facing faces readable. The camera is fitted only on the first model. In jsdom tests mock the Viewport (no WebGL).
- **Units:** everything is stored and computed in mm. Only `LengthField` converts to/from the display unit (`UnitProvider`, key `gridfinity.unit`); switching units never touches params. Use `LengthField` for any length, `NumberField` for unitless numbers. Both show − / + buttons by default (`stepper={false}` opts out): click = ±step, hold repeats (400 ms, then 10/s), Shift = ×10, limits disable the button; in inches the step is applied in the display unit and the stored mm stays exact. `ui/stepperAssert.ts` is the test helper that checks every numeric input of a panel has both buttons.
- **i18n:** no hard-coded UI text; add keys to both `en.json` and `ru.json` (a test fails if they diverge). Language key `gridfinity.lang`; `<html lang>` follows the active language.
- **Persistence:** `usePersistedState(key, defaults, migrate?)` merges stored JSON over defaults and falls back to defaults on corrupt data; pass a `migrate` function when a stored shape changes (always normalise nested objects such as `fasteners` with `features/fasteners/normalize.ts`, a partially stored value must never crash the mode) (see `features/baseplate/migrate.ts`: old `magnets`/`screws` booleans → `fasteners`, old manual coordinates → slots). One key per mode (`gridfinity.baseplate`). Storage keys keep the `gridfinity.*` prefix (and `keychain.*`) although the site is called PrintKit: renaming them would reset every visitor's settings, language and last session. The site name, GitHub URL, donation address and Metrika counter live in `app/site.ts` and so does `APP_VERSION` (= `package.json` `version`, injected as `__APP_VERSION__` by `define` in `vite.config.ts`, which Vitest shares; never write the number anywhere else). `BetaBadge` (header, next to the logo) opens the disclaimer popover; the same text and `v<version>` are in the start-page `Footer`; `CHANGELOG.md`'s top heading must carry the current version (`site.test.ts`).
- **Baseplate model** (`geometry/baseplate.ts`): `BaseplateParams = BaseplateGeometry + preview`; geometry is `{pitch, x: AxisSize, y: AxisSize, thickness, fasteners}` where `AxisSize = {mode: 'units'|'mm', value, align}` (units scale with the pitch, mm do not). `baseplateLayout` resolves cells, padding, offsets (rim included) and truncation; `baseplateHeights` gives the total height and the pocket bottom = `(baseHeight − 4.65) + max(floor, ears)`; `validateBaseplate` returns `baseplate.error.*` keys and `BaseplateMode` skips generation while invalid (`useModel(..., {enabled})`, the last valid mesh stays, export is disabled). Thickness: `baseHeight` (≥ 4.65), `floor` (0 = open frame), `rim` (outer wall around the whole plate), `paddingDrop` (how far the padding sits below the rim, 0 = flush), `cornerRadius` (default 4). Splitting is `params.split` (UI settings) → `toGeometry(p)`; the geometry's `SplitGeometry` is normalised to the default when disabled so toggling the exploded view or the gap never rebuilds. Preview-only values (build plate) live in `preview` and never trigger a rebuild. UI: `SizeSection`, `ThicknessSection`, `PlateSection`, `FastenerSection`; build-plate presets in `features/baseplate/bedPresets.ts`. In geometry tests use `sharpParams`/`units`/`mm` from `geometry/testing.ts` (square corners match the prototype's regression volumes).
- **Box model** (`geometry/box.ts`): `BoxParams = {pitch, x, y (AxisSize), height {units|mm}, thickness {outerWall, innerWall, floor}, lip, scoop {front,back,left,right,radius}, compartments, fasteners}`; persisted under `gridfinity.box` via `features/box/migrate.ts`. `boxLayout` gives the outer size (size − 0.5 mm clearance), cavity, wall top, total height (wall top + lip height), cavity bottom (foot 4.75 + floor) and the clamped scoop radius; `validateBox` (keys `box.error.*`, generation is skipped while invalid) and `boxNotices` (`box.notice.scoopClamped`). Build order in `buildBoxSolid`: feet (`binFoot`, one per full cell) ∪ body (rounded rect from foot top to total height) − cavity (prism, 45° chamfer under the lip, lip profile from `layeredHullRect`) + dividers + scoops − bottom fasteners (magnet pockets open at the underside, blind screw holes). Compartments: `xDividers`/`yDividers` are centre positions as fractions of the cavity length; `removed` holds merged segments `x:k:j` / `y:k:i`; `equalDividers` generates equal division. Not implemented (not in the spec): the artboard's separate "ledge" shelf, label tabs, lids, per-compartment heights.
- **Cutout model** (`geometry/cutout.ts`, `bin.ts`, `stl-import.ts`, `cutout-placement.ts`): `bin.ts` is the shared base of Box and Cutout (`binLayout`, `buildBinBody` = feet + body, `lipOpening`, `bottomFasteners`); Cutout leaves the interior solid, cuts the lip opening above the top face and subtracts pockets from the top face (`wallTop`) down by `depth` (limited to `wallTop − 4.75 − floor`). A `Cutout` is `{id, name, source, x, y, rotation, depth, clearance, visible, color}` with x/y = centre of its footprint box relative to the bin centre; `color` is a palette index (0–6, theme tokens `--color-cutout-N`, `features/cutout/palette.ts`) assigned by `addCutout`/`duplicateCutout` as the lowest index no other cutout uses (wrapping when all are used), kept for the cutout's life, carried to the 3D tool by `ToolMesh.color` and filled for old sessions by `fillCutoutColors` in `migrateCutout`; `source` is a rounded rectangle, a circle (`{kind: 'circle', diameter}`: 96-gon cross-section, exact bounds independent of rotation) or a mesh (`meshId`, `unit`, `orientation {faceDown, rx, ry, rz}`, `mode` projected | 3d, plus `size` and a convex `hull` kept in the params for the UI). Projected mode = `Manifold.project()` outline offset by the clearance and extruded; 3D mode = the part as it is, standing on the pocket floor (clearance = Minkowski offset with a small sphere, trimmed at the floor; scaling above 40 000 triangles), opening extended up to the top by its silhouette. Meshes that are not valid solids are healed first (`Mesh.merge()`, `fillHoles`); only if that fails a stepped pocket from cross-sections is built (`cutout-profile.ts`, cached), then the convex hull. `ModelResult.tools` carries translucent preview bodies of the cutouts (rectangle extrusion or the part's own mesh), never part of the model, volume or export; the viewport draws them in cyan with a persisted toggle (`gridfinity.viewport`). STL: `parseStl` (binary by file length, else ASCII) → `repairMesh` (weld, drop degenerate, consistent orientation, flip if the volume is negative) → `toManifold`; `orientVertices` applies units, lay-flat (`rotationToDown`), 90° steps, then centres XY and puts the lowest point at z = 0. Meshes are too big for localStorage: `features/cutout/meshStore.ts` keeps them in IndexedDB (memory fallback, `persistent` flag), the worker gets them with `ModelClient.registerMesh` and the registry `meshRegistry` in `geometry/model.ts`; params reference them by id and a missing mesh only skips that pocket. Placement helpers are pure (`centerCutout`, `alignEdge`, `distribute`, `fitFootprint`, `snapMove`); `TopView` shows live drag via a draft position and commits on release, so the model is rebuilt only then.
- **Photo cutouts** (`geometry/photo/`, `features/cutout/photo/`): the "From photo" button in the Cutout list opens `PhotoDialog` (steps: photo and paper, corners, silhouettes); its state lives in `usePhotoTrace` held by `CutoutPanel`, so closing and reopening keeps photo, corners and settings, nothing is persisted and the photo never leaves the browser. Pure pipeline: `paper.ts` (Letter 215.9 × 279.4, A4 210 × 297, custom 50–1000 mm, orientation), `homography.ts` (`homography` 8 × 8 solve, `checkQuad` = ok / notConvex / mirrored / tooSmall with corners clockwise from the top left, `rectify` samples the photo through paper → photo so there are no holes; raster 4 px/mm, longest side ≤ 2000 px), `segment.ts` (`paperSurface` fits a quadratic surface to the paper pixels with iterative exclusion of objects, so gradients and big dark objects work; ratio to that surface, `sensitivity` 0–1 mapped to a 50 %…8 % brightness drop with an Otsu-based automatic value; close, specks, `fillHoles`, edge margin, 8-connected components, min 3 mm), `outline.ts` (`traceSilhouette`: blurred mask → `traceAlpha` sub-pixel contour → largest outer loop → `simplifyLoop` 0.15 mm → mm, y up, counter-clockwise, relative to the bbox centre; `center` is paper-centred). `synthetic.ts` builds test photos through a known perspective (tests and browser checks only). `OutlineSource` (`kind: 'outline'`, polygon + size) is a cutout source like rect, circle and mesh: `baseOutline` returns its points, the pocket is `CrossSection.ofPolygons` grown by the clearance, `validOutline` guards loading. `createCutouts.ts`: `tracedCutouts` makes one cutout per kept silhouette at its paper position, `withTraced` adds them (colours by the usual rule, existing cutouts kept) and calls `fitFootprintUnits` (smallest whole units that hold all visible cutouts with wall, margin and bin clearance). **Colour, shadows and automatic corners (25a):** the photo is decoded in colour (`decodeColorImage`, `ColorImage`), `rectify` warps the colour planes too (`Rectified.rgb`), and `segment` (with rgb and `shadows` on) uses `colour.ts`: a quadratic paper surface per channel, an object is a pixel whose colour deviates from "paper colour times a factor" (`colourDeviation`, so yellow handles under flash are found) or is darker than the sensitivity drop, and the soft-shadow region is removed: `shadowRegion` grows from clean paper through pixels that get no brighter, are nearly colourless (`κ ≤ 0.12`), not darker than a drop of 0.8 and not on a *wall* (fine-scale steepness above `shadowEdge` = 0.3 per mm: edges and thin dark lines of tools, which the penumbra never reaches), and the existing hole filling restores enclosed steel parts (grey pliers head); no opening (`open` = 0), silhouettes under 60 mm² are dropped. Without rgb or with `shadows: false` the old brightness-only rule runs. Regression fixtures are the owner's two photos (`geometry/photo/fixtures/{flash,noflash}.jpg`, 480 × 640, metadata stripped, decoded in tests with the dev dependency `jpeg-js` through `fixtures/load.ts`): both give exactly three silhouettes agreeing within ~1 mm. `detect.ts` (`detectPaper`: bright, unsaturated area on a more saturated or darker table via Otsu of V and S, largest component with holes filled, convex hull, best four vertices, per-side line fits intersected for corners, clockwise from the top left, rejected when it touches the frame on many sides) and `aspect.ts` (`estimateAspect`: Zhang–He true proportions from the quad; `guessPaper` → A4 / Letter within 3 % and portrait / landscape) run when the photo is loaded (`usePhotoTrace`, `Detection`), proposing corners, paper and orientation. Dialog flow: step 1 only the photo and `PhotoTips` (seven points), then automatically step 2 with paper size, orientation and `CornerEditor` (transparent 22 px rings, `cornerGrab.ts`: grab from the area near a corner inside the sheet, relative drag, no crossing; `Loupe` 4× from the full-resolution photo, placed in the farthest corner of the visible editor with `placeLoupe`), a Tips popover on steps 2–3, step 3 silhouettes. Luminance-only limits remain only when no colour is available.
- **Export** (`export/`, `data/printers.ts`, `features/export/`): `ExportSettings` (format stl|3mf, printer id or `custom`, custom bed, edge `margin`, plate `gap`, nozzle/process/filament, `multi` one|separate, orientation, file name) is shared by all modes: a module store with `useExportSettings()` (key `gridfinity.export`, normalised by `normalizeExportSettings`). The printer bed and margin override the baseplate's stored plate size and split margin (`BaseplateMode`); `usableBed` = bed − 2·margin. `data/printers.ts` holds Bambu presets (hand-written from vendor specs, with `bambu: {model, suffix}` for Studio profile names; never copy third-party AGPL preset dumps). `buildExport(parts, settings, name)` orients each part (`orient.ts`: flip about X, rotate 90°, origin at the bbox corner, z = 0), arranges them on plates (`arrange.ts`: shelf packing, several plates, `overflow` for parts bigger than the bed) and returns STL or 3MF files (`threemf.ts` writes the ZIP with fflate: one object per part, mm, translation-only build transform). `bambu.ts` adds `Metadata/project_settings.config` + `model_settings.config` only for a Bambu printer in 3MF; the key names are version dependent and must be verified by opening a file in Bambu Studio. `ExportPanel` is the sticky block under the parameters (format, printer, download, plate status, per-part buttons), `ExportOptionsSection` is appended to every mode's panel by `Workspace`.
- **Start page art** (`src/geometry/art/`, `scripts/render-art.ts`, `src/app/art/*.svg`): every card (product cards on `/`, mode cards on `/gridfinity` and `/keychain`) shows a pre-rendered vector image keyed by `artId` (`Product.artId`, `ProductMode.artId`; `ART`/`ModeArt` in `app/ModeArt.tsx`: box, baseplate, cutout, keychainImage, keychainShape; Gridfinity card = box, Keychain card = keychainImage). Gridfinity images are the real 2×2 parts (baseplate with corner magnets, 2×2×3 box with two crossing dividers, 2×2×3 cutout block with a pocket from a sample STL). `npm run art` builds them with `generate()` in two groups (Gridfinity three with one shared scale, Keychain two, so the Gridfinity files stay byte-identical). In the Keychain group the keychain-image drawing gets the scale at which it is as tall as the box drawing (`BOX_ART_HEIGHT` ≈ 149 of 165 viewBox units, keeping the cards on `/` level — update that constant if box.svg changes) and every other picture gets the largest scale that does not exceed it and fits the field width (the shape card is wider than the paw). The keychain ones need no file: the image-mode bitmap is a paw print drawn by `geometry/art/paw.ts` (palm pad and four toes as ellipses joined by an exponential smooth minimum, anti-aliased 1000 px bitmap, symmetric and one piece), meshed at a 0.12 mm cell, and the script exits with an error after writing them if `tmp/cutout.stl` is missing. `ArtOptions.smooth` (σ in viewBox units; `smooth.ts` blurs every tone and silhouette mask and thresholds at 0.5 before tracing) is used only by the Keychain group (`KEYCHAIN_SMOOTH`) to remove the pixel stairs of the 3× raster; the Gridfinity group leaves it off. It uses `generate()`, isometric projection, a z-buffer tone image (7 tones, nested "tone ≥ k" regions) and boundary tracing; the SVG files are committed, carry only classes (`art-t0…6`, `art-edge`, colours from `theme.css` tokens) and are inlined by `ModeArt` (`?raw`), so the start page needs no WebGL, worker or WASM. Rerun `npm run art` and commit when default geometry changes. The cutout sample is `tmp/cutout.stl` (git-ignored; the script stops with a message when it is missing; CI never runs it and no test reads it). Size budget 60 KB per image is checked by `ModeArt.test.tsx`.
- **Keychain model** (`geometry/keychain.ts`, `geometry/raster/`, `features/keychain/`): the image is decoded on the main thread (`decodeImage`: PNG/JPEG/WebP/SVG → `GrayImage {gray, alpha}`, cap 4096 px, SVG rasterised at 1024) and stored in IndexedDB (`imageStore`, own DB `gridfinity-keychain`, memory fallback); the worker gets it once (`ModelClient.registerImage`, registry `imageRegistry` in `model.ts`) and params reference it by `imageId`. `KeychainParams = {imageId, silhouette, size, relief, base, quality}`, persisted under `keychain.relief` with `imageName` (`migrateKeychain` normalises nested objects). Pipeline in the worker (`generate('keychain')`, result `ModelResult.keychain` = `KeychainInfo` with threshold, mask preview, holes, size, effective cell, error key): `buildSilhouette` (Otsu/threshold, alpha wins when present, close, holes by stable scan-order ids with `keepOpen`, specks, grow) → crop to the bbox and resample to a grid (`buildGrid`, step = quality cell or larger to fit the triangle budget) → EDT → `reliefHeight` (plateau + smoothstep bevel, ≥ heightFloor, port of `02_heightfield.py`) → `reliefMesh` (block topology, flat back at z = 0, walls on shared vertices) ∪ plate outline extruded by `base.thickness` (`plateOutline`: silhouette offset, rect, rounded, circle; too small → `keychain.error.plateTooSmall`). Errors (empty mask, plate too small) return no parts; `useKeychainModel` keeps the last good mesh and flags `pending`. The raster toolkit (`otsu`, `dilate/erode/close`, `labelComponents`, `findHoles`, `fillHoles`, `edt`, `resampleMask`) is pure and unit-tested. `MaskPreview` is the collapsible overlay in the viewport corner (`Workspace overlay` prop) with an Enlarge button that opens a large dialog (~70 % of the window, Esc / outside click / close button, focus returns to the button). `PlacementEditor` draws its rulers in a margin band inside the viewBox; `Workspace` pads the panel scroller by the sticky footer height (`app/useElementHeight`). The viewport axes gizmo sits above the measurements bar (`GIZMO_BOTTOM`) and its axes are thin cylinders, not 1 px lines.
- **Keychain patterns** (`geometry/patterns/{profile,fields}.ts`, `raster/thin.ts`, `features/keychain/{ProfileSection,DetailSection,PatternSection}`): the heightfield in `buildGrid` runs source (distance, or image brightness with contrast/gamma/invert, capped by a bevel rim ceiling) → profile (`profileValue`: bevel, dome, terrace, flat, engraved; presets are data in `PRESETS`, `presetOf` returns `custom` when values differ) → detail lines (spine = Zhang–Suen skeleton + Gaussian, groove = band at a distance from the rim) → surface pattern (`coverage`: lines, crosshatch, dots, hex, ripples; crisp 0/1 masks in keychain coordinates, subtracting `depth`, never below the floor; scope relief | plateau | base) → clamp. `Grid.top` holds absolute heights including the plate, so `reliefMesh` has no base parameter. - **Keychain modes** (`features/keychain/`): `KeychainWorkspace` (model hook, `Workspace`, export footer, session record) is shared; `ImageMode` (state `keychain.relief`, image store, drop zone, `KeychainPanel` = image/silhouette/size + `SharedSections`) and `ShapeMode` (state `keychain.shape`, `ShapePanel` = `ShapeSection` + `RimSection` + `SharedSections imageOnly={false}`, i.e. no Relief or Detail lines sections). `SharedSections` is relief, detail (both only with `imageOnly`), pattern, base, mount, split, resolution. Geometry: `KeychainParams.origin = {kind:'image'} | {kind:'shape', shape}`; `geometry/shapes.ts` has `ShapeParams` (rect, circle, ellipse, capsule, polygon with rounding/rotation, `rim`), analytic `shapeInside`, `shapeBounds` (exact bbox in mm) and `shapeMask` (2048 px, bbox fills the raster exactly) which feeds the same `buildGrid` as an image mask, bypassing threshold, areas and brightness. Polygon `width` is the circumscribed diameter; the corner radius is a true fillet (Minkowski of a smaller polygon with a disc) so the extreme width does not change. Outlines are exact, not grid-stepped: the shape is rasterised with a 1.75-cell margin, the relief is intersected with `shapeCrossSection` (`geometry/shapeOutline.ts`, 256 segments per circle) and a silhouette plate is that outline offset, with `edgeShift` keeping edge distances true; the mount field uses the unpadded mask. - **Smoothing** (`geometry/raster/blur.ts`, `ProfileSection`): `SourceParams.smooth/despeckle` (brightness plane: 3×3 median over silhouette nodes, then masked Gaussian, before contrast/gamma; the UI sets 0.4 mm when brightness is chosen, stored default and old records are 0) and `ReliefParams.smooth` (0–3 mm; blurs the finished height `raw` before the bevel ceiling of the brightness source, detail lines and patterns, then clamps to `heightFloor`). The filters are normalised convolutions (`G*(v·m)/G*m`) so nothing leaks across the silhouette or from `fixed` nodes; σ = radius/cell clamped to 0.5–40 cells (`sigmaCells`). Fields are optional in the types (missing = 0) and `migrateKeychain` coerces them. `smoothResolution` drives the "radius below one grid cell" warning with the raise-resolution button. Smoothing controls live in the Relief section, which only Image mode has; Shape mode is a flat plateau and has none.

In `buildGrid` nodes of level areas (via `GridInput.levels` + `resampleIds`) get a flat `base + max(level, heightFloor)` and are `fixed` for the brightness/surface smoothing, skipping profile, detail lines and patterns. - **Text** (`geometry/text.ts`, `features/keychain/{TextSection,textRaster,fonts,fontList,fontStore,useTextRaster}`): `KeychainParams.text` (`TextParams`: content, `font {id,bold,italic,name?}`, size = cap height mm, letter/line spacing, align, rotation, emboss|engrave with height/depth, x/y = fractions of the silhouette box, Y up) is shared by both modes (`SharedParams`). The main thread rasterises the text with canvas at 12 px/mm (`rasterizeText`: pixel size from the measured height of "H", `layoutLines` is the pure layout) and registers the alpha mask once in the worker (`ModelClient.registerText`, `textRegistry`); params sent to the worker carry `text.maskId` = `textRasterKey` (content, font, size, spacings, align only), so moving or rotating text never re-rasterises (the worker applies the inverse transform in `textSampler`). `useTextRaster` (in `KeychainWorkspace`) keeps the previous raster until the new one is ready and exposes `TextRasterContext` (font lost, busy). Letters are built as exact solids, not from grid nodes: `textOutline.ts` traces the alpha raster (marching squares with sub-pixel interpolation, Douglas–Peucker 0.02 mm) into polygons, and `applyExactText` extrudes them from just under the surface to surface + height (emboss) or cuts them from surface − depth, never below `base + heightFloor` (engrave); the part over the silhouette and the part over the plate outside it use their own levels and are clipped to the silhouette/plate outlines. This path is taken when the relief under the letters is flat (spread ≤ `TEXT_FLAT_TOL` = 0.15 mm: plateau, plate, level areas); otherwise (letters across a bevel, dome, brightness) the fallback samples the text in `buildGrid` (emboss `+height`, engrave `max(t − depth, min(t, lo))`) with stepped edges and, when text leaves the silhouette and a plate exists, `plateInGrid` is switched on (stepped plate, like base patterns); `textRegion` samples where text lies (`info.text.clipped` = part outside silhouette and plate, not built). Two halves: `buildKeychainParts` = `buildKeychainCore` for the top plus a second core call without text for the mirrored bottom. Fonts: 25 fontsource families (latin + cyrillic only) listed in `fontList.ts`, woff2 files are lazy `import.meta.glob(..., {query:'?url'})` loaders registered with `FontFace` on first use (no third-party hosts; variable packages for most, static for Fira Sans, PT Sans/Serif, Russo One, Press Start 2P, Pacifico, Lobster, Marck Script); generic families and a user TTF/OTF/WOFF (validated by magic bytes, stored in IndexedDB db `gridfinity-keychain-fonts`, restored by `ensureFont`) complete the list. `PlacementEditor` has a `text` target (box, baselines and the text drawn to scale, drag, X/Y) and a text-only mode (`only="text"`) embedded in `TextSection`. `textResolution` drives the fine-strokes warning (stroke ≈ size/8 < 4 cells).
