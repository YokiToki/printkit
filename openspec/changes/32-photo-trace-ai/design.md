# Design

## Context

Today `usePhotoTrace` builds `rectified = rectify(photo, corners, paper, rgb)` (4 px/mm, ≤ 2000 px) and `segmentation = segment(rectified, {margin, sensitivity})`. A `Segmentation` is `{width, height, scale, labels (Int32 per pixel, 0 = background), silhouettes[{id, areaMm2, widthMm, heightMm, bbox}], sensitivity, defaultSensitivity}`. Everything downstream (`traceSilhouette`, `tracedCutouts`, the silhouette list, click selection, the dialog's preview) reads only that structure. This is the seam: an AI engine has to produce a `Segmentation`, nothing else changes.

Why the straightened sheet is a good input for a network: it is a top view at true scale with the table cropped away, so the network sees only paper and objects, the foreground is by construction "everything that is not the sheet", and mm ↔ pixel is known (4 px/mm).

## Goals / Non-Goals

**Goals:**
- An alternative engine behind the same `Segmentation`, selectable per session, default unchanged.
- The baseline is provably untouched and is the yardstick.
- No photo leaves the browser; weights are downloaded only after consent.
- A decision on the model backed by numbers on the fixtures.

**Non-Goals:**
- Replacing or tuning the classic segmenter. Click prompts. Server inference. Non-commercial weights.

## Decisions

- **Engine as data, not as a fork.** `type SegEngine = 'classic' | 'ai'` lives in `PhotoSettings.engine` (default `'classic'`). `usePhotoTrace` keeps `segmentation` (classic, as now) and adds `aiSegmentation` computed only when the engine is `ai` or the compare view is on; the exposed `active` segmentation is chosen by the engine. `segment.ts`, `colour.ts`, `outline.ts` are not modified, only imported. Alternative: an `if` inside `segment()`. Rejected: it would touch the baseline and make its regression harder to prove.
- **Input and resolution.** The rectified RGB is resampled to the model's input (typically 512 or 1024 px for BiRefNet-lite, 320 for U²-Net-P), run, and the alpha is resampled back to the 4 px/mm raster (bilinear). A4 at 1024 px is ≈ 0.29 mm/px, so the network edge is only good to about ±0.5 mm: this is why the edge is refined (next point) and why the result is never used raw for the default.
- **Model choice by measurement (task 1).** The PoC (`poc/ai/`, results in `poc/ai/FINDINGS.md`) ran the candidates on the owner's photos: BiRefNet-lite at 1024 fails with `std::bad_alloc` on both backends and is dropped; RMBG-1.4 (non-commercial) gave the best result in ~6 s on WASM; ISNet loses a whole tool; U²-Net-P is fast but not better than the classic path; WebGPU brings no gain over WASM. Second round: InSPyReNet fp16 (MIT, WebGPU ~2 s, good), ormbg (Apache-2.0, WASM 15–20 s, good), ISNet imgly fp16 (MIT, WebGPU 0.25 s, misses part of the cutters), BiRefNet-lite 512 fp16 (MIT, 98 MB, good, WASM ~9 s, empty mask on WebGPU), U²-Net full (shadow leaks); MVANet and BEN2 mark the whole sheet and are dropped. The set offered in the manager comes from these results: InSPyReNet fp16 (WebGPU), BiRefNet-lite 512 fp16 and ormbg (WASM) as the recommendations, ISNet imgly fp16 as the fast option (its missed cutter parts are expected to come back with a lower threshold; to be confirmed on the PoC). A note: most networks lose part of the cutters, which the classic path finds, so the AI engine is an alternative for hard photos, not a better default. MODNet is portrait-only and excluded; `finegrain-box-segmenter` (396 MB) is excluded for size. The default AI engine uses the best candidate that reaches the targets in the table below; a second, smaller model may be offered as "lighter". If none reaches them the change stops after task 1 and records the numbers (the change is then archived as a negative result without a version bump, via `/opsx:update`).

  | Target on the two fixtures | Value |
  |---|---|
  | Tools found | 3 per photo, none merged or split |
  | Size of each silhouette vs the baseline | within 1.0 mm (raw network), within 0.5 mm (hybrid) |
  | Silhouette IoU vs the baseline | ≥ 0.97 (hybrid) |
  | Time for one A4 on a laptop, WASM / WebGPU | ≤ 15 s / ≤ 3 s (informational) |

- **Salient-object networks and shadows.** These networks were trained to cut out objects and usually leave a cast shadow out (the argument in `PREPROP_CUTOUT_GOOGLE.md`), but "usually" is not a guarantee, and thin dark parts (pliers jaws) can be eaten. The harness therefore reports, per fixture, the area difference to the baseline split into "network larger" (shadow leaked) and "network smaller" (part lost).
- **Mask → silhouettes.** Threshold the alpha at 0.5, then the same cleanup steps the classic path uses, imported from `geometry/raster` (`close`, `fillHoles`, `removeSpecks`, `labelComponents`, edge margin, `minSize`/`minArea` from `defaultSegmentParams`). The numbering rule is the classic one (top to bottom), so list order and colours are identical between engines for the same objects. Pure function `aiSegmentation(rectified, alpha, params) → Segmentation`, unit-tested on stored alphas.
- **Mask tuning (threshold and smoothing).** The network returns a soft alpha (0…1) with a soft zone along every edge. Two controls turn it into a silhouette, both applied to the cached alpha so the network is not re-run: a **threshold** (default 0.5, range 0.05…0.95; lower grows the outline into the soft zone, higher shrinks it) and a **smoothing radius** in mm (default 0.3, range 0…3; masked Gaussian from `geometry/raster/blur.ts` on the alpha before the threshold, σ = radius × scale, never below `MIN_SIGMA`). Smoothing evens out wavy and stair-stepped edges (the 1024 px output is stretched to 4 px/mm) and merges hairline cracks; too much removes thin parts, so the list shows each silhouette's size change and a hint appears when a silhouette shrinks by more than 1 mm. The PoC page already has both sliders with live recalculation, a greyscale view of the soft alpha, the outline length (shorter = smoother) and the area of the soft zone; the defaults and the size of the soft zone in mm are taken from its measurements. The two controls are user-facing and always visible under the AI engine (labels "Edge reach" / "Outline smoothness" with a one-line hint each and the numeric value; the technical names stay in code). Defaults are per model: the registry has `maskDefaults: {threshold, smooth}` for each entry (e.g. a lower threshold for ISNet, whose mask is tighter), found with the PoC sliders; switching the model loads them unless the user has touched the controls for the photo, and Reset returns to them. The values are session state of the dialog (`PhotoSettings.ai = {threshold, smooth}`), per photo not persisted, with a reset. With the hybrid edge the classic colour test places the final edge inside a band around this mask, so the two settings mainly decide which object parts count and how the band is placed; the traced outline is then smoothed by `traceSilhouette` as for the classic engine (σ = 1 px, 0.15 mm simplification).
- **Hybrid edge.** For each silhouette: band = mask dilated by `band` mm (default 1.5) minus mask eroded by `band`. Inside the band the classic paper-colour deviation (`colourMask` from the paper surface fitted by `paperSurface`; `paperSurface` and `colourMask` are called, not changed) classifies pixels; the refined mask is `eroded core ∪ (band ∩ classic object pixels)`. If the classic test marks the whole band as paper or as object on a stretch longer than a few mm (the dark-part-in-shadow case), that stretch keeps the network edge. The refined labels go through the same `traceAlpha` as today. A setting `refine: on|off` (default on) exists in the compare view so the raw network edge can be inspected; it is not a persisted user option beyond the session.
- **Compare view.** `CompareOverlay` draws the other engine's silhouette outlines (already traced by `traceSilhouette`) as dashed lines over the straightened view, plus a table "tool: classic mm / AI mm / Δ". It costs one extra segmentation when open, and is the way the user, and the owner while developing, sees where the engines disagree.
- **ML runtime.** `src/ml/` is React-free. `matte(rgb, w, h) → Float32 alpha` is the only adapter this change needs. `ml.worker.ts` owns the inference session; `mlClient.ts` mirrors `modelClient.ts` (latest request wins, stale replies dropped); the worker is created lazily so classic users pay nothing, not even the library chunk (dynamic import). Backend: try WebGPU, fall back to WASM single-threaded (no COOP/COEP on Pages); report the backend in the model manager.
- **Model manager (a window of its own).** `ModelManager` is a dialog reachable from the engine switch and from the app footer. It lists every model of the registry with: name, what it is good for (fast / accurate), download size, licence, status (not downloaded / downloading with progress / ready / failed), and the buttons Download, Cancel, Delete, plus the total space used and a "Delete all". Several models can be downloaded at the same time as separate entries; the user picks the active one for the AI engine (a radio in the list). Weights live on the client only: Cache API under a versioned key (revision hash), with a memory fallback and a notice when the browser refuses storage. Nothing downloads without the click; choosing AI with no model ready opens the manager. The first download of a model shows its consent text (below).
- **Licences.** Only models under permissive licences (MIT, Apache-2.0, BSD, CC0) are offered. Non-commercial and copyleft weights are excluded: RMBG-1.4 (Bria, non-commercial) gave the best raw result in the PoC but is left out, because with the mask tuning below the permissive models reach a good result too (decision of the owner after the PoC), and the project stays free of licence caveats. The first download of any model shows its name, size, source host and licence and starts only after the click; the References page and the README list every model with its SPDX id and source. The PoC page keeps RMBG-1.4 marked `referenceOnly` as a quality yardstick; it is not part of the product registry.
- **Pinned weights.** The registry (`src/ml/models.ts`) holds per model: id, URL with a commit hash (not `main`), byte size, SHA-256 (verified after download), input size and normalisation, SPDX licence, source. A model enters the registry only with MIT / Apache-2.0 / BSD / CC0. The References page and README list them from this registry (a test checks every registry entry appears).
- **Backend per model.** The registry lists for each model the backends it works on and the preferred one, from the PoC: InSPyReNet fp16 and ISNet imgly fp16 are WebGPU-only (fp16 on WASM gives an empty mask or minutes), ormbg and U²-Net fail on WebGPU (`ceil_mode` in MaxPool) and run on WASM, RMBG-1.4 int8 runs on WASM faster than on WebGPU. The manager shows only models that the device can run (WebGPU and `shader-f16` detected at start) and marks the others as unavailable with the reason; a run that fails on the preferred backend is not silently retried on another unless the registry says it works there.
- **Mobile and weak devices.** The AI option is available at any width, but the dialog states the size, and on narrow screens or without WebGPU the lighter model is suggested first. The classic engine is always one click away and is what runs if the AI path fails (error banner, `active` falls back to classic).
- **Testing.** Unit tests never run a network. Frozen model outputs (alpha PNGs produced by the harness for each fixture and each chosen model, a few hundred KB) are committed under `geometry/photo/fixtures/ai/` and drive the post-processing tests. Component tests mock `mlClient`. The classic baseline has a new frozen-output test (silhouette count, bbox, area per fixture) next to the existing `photoFixtures.test.ts`, so any accidental change to it fails.
- **Rollout.** The engine switch is always visible, Classic selected. No flag.

## Risks / Trade-offs

- [The network does not beat the baseline on the owner's photos] → task 1 is a gate; the hybrid edge and the compare view are built only after it passes.
- [Network edge is "puffy" at 1024 px] → hybrid refinement; targets measured on the refined result.
- [Shadow leaks into the mask or a dark part is lost] → the band search clamps leaks to the classic edge where classic is reliable; lost parts are visible in the compare view and the user can switch engine.
- [100–300 MB download on mobile] → explicit consent with the size, the lighter model offered first on mobile, cancel, cache.
- [Library size and WASM files bloat the bundle] → dynamic import in the worker only on first AI use; the classic start-up path does not load them (checked in the build output size and the network panel).
- [Hugging Face availability, revision changes] → pinned hashes and SHA-256; on a failed download the error says which host failed and classic keeps working.
- [Single-threaded WASM is slow] → progress indicator, `computing` flag as for the classic path; measured in task 1, the lighter model is the WASM default.
- [Licence drift] → registry test refuses entries without an allowed SPDX id or without a pinned revision.

## Open Questions

- Is a request to huggingface.co acceptable at all (it reveals the IP), or must the weights be self-hosted (Cloudflare R2)? The design assumes huggingface.co with consent; self-hosting only changes the URLs in the registry.
- Which devices are the minimum target (an iPhone, a weak Android)? It decides whether the WASM path of BiRefNet-lite is shipped or only the light model.
- Click-to-select with SlimSAM / SAM 2.1-tiny is the strongest answer to touching and merged tools. It reuses the same runtime and the `Segmentation` seam and is proposed as the next change after the automatic path is measured.
