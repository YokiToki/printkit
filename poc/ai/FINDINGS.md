Запуск: `npm run poc:ai` → http://localhost:5198 (`POC_COI=1` включает COOP/COEP). ## Выводы
1. Бэкенд: ORT Web, один воркер, WebGPU → WASM. Для лёгкой модели WASM в одну нить достаточен (< 1 с на лист), COOP/COEP не нужны.
2. BiRefNet-lite с входом 1024 в этом окружении не запустился ни на WebGPU, ни на WASM (нехватка памяти). Вход у ONNX зафиксирован 1024, уменьшить нельзя. Либо искать/конвертировать вариант с входом 512, либо проверять на другом устройстве в обычном Chrome (память Browser pane могла быть причиной).
3. ISNet int8 на 1024 px и одной нити непригоден по скорости на WASM.
4. U²-Net-P: на снимке со вспышкой почти идентичен классике, на снимке без вспышки теряет часть тёмной/синей ручки: именно тот случай, где нужен гибридный край и сравнение с классикой, и где важна модель посильнее.
5. Нюансы реализации: при `wasm.proxy` тензоры и буфер модели передаются (transfer) и становятся detached: тензор создаётся заново на каждый запуск, буфер модели нельзя использовать повторно; без proxy инференс блокирует страницу.
6. Лицензия RMBG: карточки Hugging Face — `license: other` (bria-rmbg-1.4/2.0, «source-available for non-commercial use»), RMBG-2.0 к тому же gated.

## Что отсюда следует
1. BiRefNet-lite отпадает как основной вариант (ORT Web, вход 1024, не хватает памяти на обоих бэкендах).
2. WebGPU не даёт выигрыша: для int8-моделей он медленнее или равен WASM, а часть операторов не поддержана. Бэкенд по умолчанию: WASM; WebGPU только как опция после замера.
3. Единственная модель с хорошим результатом, RMBG-1.4, имеет non-commercial лицензию. Разрешённые (MIT/Apache) модели либо не запускаются (BiRefNet), либо хуже классики (ISNet теряет предмет, U²-Net-P не лучше).
4. Потеря целого предмета (ISNet, кусачки) не лечится гибридным краем, потому что тот только уточняет границу уже найденной маски. Если ИИ-движок остаётся, объединение «классика ∪ сеть» или проверка классических силуэтов сетью надёжнее, чем сеть как единственный источник.

## Выводы второго раунда
1. WebGPU полезен не всегда, но для моделей без `ceil_mode` MaxPool даёт ускорение в десятки раз (ISNet imgly 0.25 с, InSPyReNet 1.9 с против 15–78 с на WASM). Значит, выбор бэкенда делается **для каждой модели отдельно**: в реестре у модели список поддерживаемых бэкендов и предпочтительный; fp16-модели работают только на WebGPU (на WASM — пустая маска или медленно).
2. Кандидаты по разрешённым лицензиям: **InSPyReNet fp16 (MIT)** — хорошее качество и ~2 с на WebGPU; **ormbg (Apache-2.0)** — хорошее качество, но только WASM, 15–20 с; **ISNet imgly fp16 (MIT)** — мгновенно, но теряет часть кусачек. Из non-commercial: **RMBG-1.4** — лучшее качество, 6 с на WASM.
3. Без WebGPU разрешённых быстрых вариантов с хорошим качеством нет: остаётся ormbg (15 с) или RMBG-1.4 (6 с).
4. Остаётся проверить: снимок noflash на этих моделях, BiRefNet-lite 512, многопоточный WASM (`POC_COI=1`) для ormbg и RMBG-1.4.

## BiRefNet-lite 512 (MIT), прогон владельца (flash, 1 нить)

| Вариант | WebGPU | WASM |
|---|---|---|
| fp16 (98 МБ) | пустая маска | хорошо, 9.4 с |
| fp32 (192 МБ) | пустая маска | хорошо, 9.1 с |

Вывод: на входе 512 модель запускается и даёт хороший результат, но только на WASM (~9 с); WebGPU даёт пустую маску даже в fp32, значит дело в самом WebGPU-пути для этой модели, а не в fp16. Это первый разрешённый вариант с хорошим качеством, работающий без WebGPU. fp16 не быстрее fp32 на WASM, поэтому для WASM берётся меньший по размеру файл (fp16, 98 МБ), если качество совпадёт.

## Решение владельца
С регулировкой порога и сглаживания маски достаточно моделей с разрешёнными лицензиями (даже ISNet даёт хороший результат), поэтому RMBG-1.4 в продукт не берётся и остаётся в PoC только как эталон качества (`referenceOnly`). Классы лицензий и согласие на non-commercial из плана убраны.

### Решение владельца (2026-10-21)
Глубина полезна, поэтому в плане `34` форма строится как смесь трёх источников (контур, глубина, детали) с долями, которые задаёт пользователь, плюс кроп области. В PoC добавлен «Комбинатор формы»: берёт маску и глубину из запусков моделей на одном снимке (режим «весь снимок») и яркость, показывает смешанную высоту и затенённый рельеф.

### PoC пайплайна Keychain (index.html) и PoC фото-вырезов (cutout.html)
`npm run poc:ai`: `/` — Keychain по этапам (1 изображение и кроп → 2 силуэт: модель маски, яркость или весь кадр → 3 глубина: модель глубины, считается по кропу → 4 детали: локальный контраст → 5 смесь контура, глубины и деталей → 3D-рельеф на three.js с орбитой и подсветкой); `/cutout.html` — сравнение с классикой для change 32. Модели силуэта и глубины выбираются отдельно и считаются независимо; результаты хранятся до смены снимка.
